## Reference behavior (source-derived)

### A. The apparatus

1. **The machine is two blocks: a body tile and a delegating top.** One block class is constructed twice — a body (`thaumatorium`) and a top (`thaumatorium_top`) — each wiring its own tile (`common/blocks/crafting/BlockThaumatorium.java:32-48`); both blocks are registered (`common/config/ConfigBlocks.java:330-331`; fields `api/blocks/BlocksTC.java:146-147`) and both tiles are registered (`common/config/ConfigBlocks.java:399-400`). The language file names both "Thaumatorium" (`assets/thaumcraft/lang/en_us.lang:339-340`). The body is the whole machine — a one-slot inventory, an aspect container, an Essentia transport, and a ticker (`common/tiles/crafting/TileThaumatorium.java:49`; its constructor `:65-79`); the top carries no state of its own (`common/tiles/crafting/TileThaumatoriumTop.java:16-22`). Neither block is in a creative tab (`common/blocks/crafting/BlockThaumatorium.java:33-37`), the top renders invisibly in the world while the body renders a model (`:54-68`), and the tile renderer floats the currently displayed output above the front of the machine (`client/renderers/tile/TileThaumatoriumRenderer.java:28-60`).
2. **The top facade forwards everything and re-links itself every tick.** Until it finds the body tile below, it resolves its link on each update (`common/tiles/crafting/TileThaumatoriumTop.java:24-31`); afterwards every container call — add, take, containment — forwards to the body and returns a neutral default when unlinked, while acceptance ignores the link and simply accepts (`:34-72`); every transport call forwards the same way — connectability, input/output faces, suction, Essentia type/amount, take/add, minimum suction (`:75-142`); the aspect view is the body's own list (`:144-158`); the one inventory slot is delegated in full (`:160-192`); and the sided-inventory face is slot zero with insert and extract allowed on every side (`:204-214`). It reports a null name (`:237-247`), and a few delegations run unguarded if the link is broken (`:216-235`, `:249-251`).
3. **The structure is a column: crucible at the base, the machine body on top of it, the top block above, heat under the crucible.** The body reverts to the alchemical construct block whenever the block below it stops being a crucible (`common/blocks/crafting/BlockThaumatorium.java:102-110`); the heat scan reads the block two below the body — one below the crucible (`common/tiles/crafting/TileThaumatorium.java:145-149`); and the language file tells the player that a crucible forming the base needs no water but still needs a heat source (`assets/thaumcraft/lang/en_us.lang:1367`).
4. **A Salis Mundus trigger on an alchemical construct column over a crucible creates it, gated on the `THAUMATORIUM` research.** The blueprint is one column — alchemical construct (top), alchemical construct (body), crucible (base) — with both construct parts marked apply-player-facing (`common/config/ConfigRecipes.java:111-116`); a blueprint layer maps top-down, so array layer zero is the top of the column (`common/lib/crafting/DustTriggerMultiblock.java:34-40`, `:154`), and the player-facing rule is `:139-145`; the trigger refuses to run unless the research is known (`:44-46`) and schedules the parts through the standard swapper (`:168-175`). The machine never drops as itself: either half breaks down to the alchemical construct block, and breaking one half converts the other (`common/blocks/crafting/BlockThaumatorium.java:82-100`).

### B. The crucible-recipe catalog interface

5. **The machine crafts crucible recipes and nothing else.** The recipe type is `CrucibleRecipe` — a research key, an output stack, a catalyst ingredient, and an aspect requirement list (`api/crafting/CrucibleRecipe.java:10-33`) — the same type the crucible uses ([alc-00-evidence.md](alc-00-evidence.md) item 4). Recipes live in the shared crafting catalog keyed by resource location (`api/ThaumcraftApi.java:85-87`, `:219-221`), and the machine resolves them by integer hash (`:241-247`).
6. **The hash is a content hash and is the recipe's identity inside the machine.** It is computed at construction from the research key, the output stack and its NBT, and every matching catalyst stack and its NBT, folded into a Java string hash (`api/crafting/CrucibleRecipe.java:35-48`); the machine persists lists of these hashes, ships them to clients, and re-resolves them through the catalog (`common/tiles/crafting/TileThaumatorium.java:92-102`, `:105-116`, `:151-160`, `:176-184`). A hash that no longer resolves is dropped on read (`:95-101`), so the hash is the durable identity across save/reload, the network packet, and the GUI.
7. **The selection list is the strictly-known, catalyst-matching slice of the catalog plus anything already registered.** The list is rebuilt by walking every catalog entry, keeping the crucible recipes the player knows strictly — complete research, with `@`-staged keys counted as known — whose catalyst matches the input slot, adding back any hash already registered in the machine, and sorting the result by output display name (`common/tiles/crafting/TileThaumatorium.java:444-469`, `:488-500`; the strict check is `api/capabilities/ThaumcraftCapabilities.java:70-88`). It is recomputed on GUI construction and on every tick of an open container (`common/container/ContainerThaumatorium.java:29`, `:32-35`; `client/gui/GuiThaumatorium.java:56`), and it is empty while the input slot is empty (`common/tiles/crafting/TileThaumatorium.java:447`).
8. **Matching is ingredient apply plus aspect containment.** The catalyst test is the ingredient's apply test; the full match test additionally requires every required aspect to be present in the store (`api/crafting/CrucibleRecipe.java:50-61`). The machine uses the full test once — as the completion re-check (`common/tiles/crafting/TileThaumatorium.java:220`).

### C. Selection: the GUI surface and the packet

9. **Right-clicking either half opens the same screen; the top redirects to the body.** The block opens GUI id 3 on the server for a non-sneaking player, using the clicked position for the body and the position below for the top (`common/blocks/crafting/BlockThaumatorium.java:70-80`; the id constant is `common/lib/RefGui.java:8`; the client screen and server container mappings are `proxies/ProxyGUI.java:87` and `:156`). Sneak-clicking does nothing.
10. **The screen shows the catalyst slot, the aspect requirements with fill bars, the selectable outputs, and a formula counter.** It is a 175×216 container screen bound to the GUI texture (`client/gui/GuiThaumatorium.java:42-58`); the background layer refreshes its display list every 500 ms from the registered hashes plus the current selection list (`:66-78`), draws page arrows when more than six entries exist (`:79-94`), draws the registered/max counter once more than one formula is possible (`:96-105`), and draws the aspect section for the time-cycled registered formula — two aspects per row, at most eight, each with a twelve-pixel bar filled by stored-over-required and the aspect's required amount in its tooltip-style tag (`:120-165`); up to six output icons are drawn in two columns of three with item tooltips (`:167-219`), each overlaid with a marker when its hash is registered and brightened while it is the time-cycled one (`:221-247`).
11. **Clicking an output toggles that formula through a packet handled server-side.** The click sends the body position and the recipe hash (`client/gui/GuiThaumatorium.java:249-272`; packet fields `common/lib/network/misc/PacketSelectThaumotoriumRecipeToServer.java:25-38`); the server handler removes the formula if it is already registered — dropping its stored requirement copy and player, and resetting the current pick — or, when the registered count is below the cap, adds it from the current selection list with its requirement copy, the acting player's name, and its hash (`:40-84`). Page arrows change the visible page of icons and play the click and select sounds (`client/gui/GuiThaumatorium.java:281-309`).
12. **A registered formula carries its requirement copy, its hash, and the player who registered it.** The three parallel lists are the machine's durable formula state (`common/tiles/crafting/TileThaumatorium.java:52-54`); the copy is taken from the live recipe at registration (`common/lib/network/misc/PacketSelectThaumotoriumRecipeToServer.java:68`), and the registering name is what later receives the crafting event (item 24).
13. **Mnemonic Matrices raise the formula cap by two each and pop off when detached.** The cap starts at 1 and adds 2 for each Mnemonic Matrix placed on the body's or top's sides — or above the top — whose facing points back at the machine (`common/tiles/crafting/TileThaumatorium.java:401-427`); the matrix only places when it can face the machine and drops itself when the faced block stops being the machine (`common/blocks/devices/BlockBrainBox.java:57-72`); lowering the cap trims the tail of the registered hash list (`common/tiles/crafting/TileThaumatorium.java:419-426`) — only the hashes are dropped there, leaving the companion requirement and name lists longer than the hash list, a latent index desync if a formula is registered again later. It is named "Mnemonic Matrix" (`assets/thaumcraft/lang/en_us.lang:341`), crafted under the `THAUMATORIUM` research (`common/config/ConfigRecipes.java:251`), and the language file states the rule as each matrix adding two formulas (`assets/thaumcraft/lang/en_us.lang:1367`).

### D. Heat, redstone, and the run loop

14. **Heat is a boolean gate: lava, fire, any Nitor, or magma below the crucible.** The scan accepts a lava or fire material, any of the sixteen dyed Nitor blocks, or a vanilla magma block, at the position two below the body (`common/tiles/crafting/TileThaumatorium.java:145-149`; the Nitor registration is `common/config/ConfigBlocks.java:291-293`). It is re-evaluated at start and every 40 ticks (`common/tiles/crafting/TileThaumatorium.java:165-168`), and nothing is consumed — there is no fuel item in this machine; the heat source is purely a gate.
15. **Redstone pauses the machine.** Indirect power at the body, the crucible below, or the top above blocks the working loop (`common/tiles/crafting/TileThaumatorium.java:397-399`, used at `:170`), so a signal anywhere on the column stops progress and lifts when removed.
16. **The working loop runs every five ticks while heated and unpowered.** With an empty input slot it clears suction and stops (`common/tiles/crafting/TileThaumatorium.java:170-174`); otherwise it re-checks or re-picks the formula, evaluates the requirement, and either completes or pulls one step (`:175-203`). The cadence is the counter's five-tick modulus (`:170`).
17. **The formula is auto-picked from the registered list by catalyst.** Whenever the current pick is invalid or its catalyst no longer matches the input, the machine scans the registered list in order and takes the first recipe whose catalyst matches (`common/tiles/crafting/TileThaumatorium.java:175-184`); a single registered formula therefore runs fully automatically, while several formulas sharing a catalyst resolve to the earliest registered one until the GUI changes the list. Formula removal resets the pick (`common/lib/network/misc/PacketSelectThaumotoriumRecipeToServer.java:59`).

### E. Essentia pulling

18. **The requirement copy drives suction: the first deficit in aspect-tag order is advertised.** Each cycle walks the registered requirement copy in aspect-tag order, takes the first aspect that is short as the suction aspect, and — when nothing is short — completes the craft (`common/tiles/crafting/TileThaumatorium.java:188-202`; the sort is `api/aspects/AspectList.java:71`). The transport view reports that aspect as suction type with a fixed suction strength of 128 whenever one is set, and untyped zero otherwise (`common/tiles/crafting/TileThaumatorium.java:336-348`).
19. **The pull is a direct one-unit drain from the first acceptable neighbour on the body/top shell.** The probe covers the three non-front horizontal neighbours of the body, the three non-front horizontal neighbours of the top, and the block above the top — it never probes below the body or the front (`common/tiles/crafting/TileThaumatorium.java:236-259`); a neighbour must be a connectable Essentia transport toward the machine (`api/ThaumcraftApiHelper.java:69-75`), must hold Essentia, must apply suction below the machine's 128, and must not demand a minimum suction above it (`common/tiles/crafting/TileThaumatorium.java:244-253`); one unit is then taken and added (`:248-251`). Jars, alembics, or tubes can all serve as the source ([alc-02-evidence.md](alc-02-evidence.md)); one unit per working cycle is the machine's whole throughput.
20. **Intake is capped at the requirement; everything else is refused.** The container add accepts only aspects of the current formula, up to the exact required amount, and returns the remainder (`common/tiles/crafting/TileThaumatorium.java:261-272`); the transport add does the same and only on input sides (`:365-368`); every side except the front is an input side and no side is an output side (`:320-333`); the containment surface reports stored amounts but never accepts or gives lists (`:274-308`). One ordering wrinkle: the add path reads the active formula before guarding for its absence (`:261-264`), so an external push with no active formula hits the dereference rather than a clean refusal.
21. **Every accepted unit is synced to clients.** Each add marks the tile dirty and notifies clients with the sync tag (`common/tiles/crafting/TileThaumatorium.java:266-271`), which carries the stored amounts, the cap, and the hash list (`:105-116`); the stored amounts stay private to the body, with the top facade presenting them as its own container view (`common/tiles/crafting/TileThaumatoriumTop.java:144-158`).

### F. Catalyst, completion, and output handling

22. **Completion consumes one catalyst, re-checks the formula, and replaces the store with an empty one.** The final check requires the current formula to still match the store and the input, then one input item is consumed (`common/tiles/crafting/TileThaumatorium.java:219-220`); the stored aspect list is discarded wholesale and replaced with a fresh empty list (`:221`) — so any overstock (for example a formula switch that left more of an aspect than the new formula needs) is destroyed rather than returned; the result is resolved from the formula hash (`:151-160`, `:222`).
23. **The result goes out the front: into an inventory there, or into the world with a nudge.** The shared ejection helper first inserts the stack into the block in front through its item handler and, for whatever remains, spawns an item entity at the front with outward motion (`common/lib/utils/InventoryUtils.java:101-123`); the machine passes its facing and the recipe output (`common/tiles/crafting/TileThaumatorium.java:227-228`), plays a lava-extinguish style sound at low volume with a randomized pitch (`:229`), clears the pick (`:230`), and syncs (`:231-232`).
24. **The registering player is credited with the crafting event while online.** The machine resolves the registering name to a player and fires the standard crafting event with the output and the remaining input stack (`common/tiles/crafting/TileThaumatorium.java:222-226`); with that player offline, the craft still completes but no event fires.
25. **Only the catalyst and the stored Essentia are touched.** A multi-item input stack is consumed one item at a time; there is no second slot and no per-craft byproduct; the crucible below is never read, filled, or drained, and heat is never consumed (items 14, 19, 22).

### G. The automation surface

26. **The single slot is automation-visible from all six faces on the body, and the top exposes the same slot as a sided inventory.** The body reports slot 0 for every face (`common/tiles/crafting/TileThaumatorium.java:392-395`), its base class accepts any item and always allows extraction (`common/tiles/TileThaumcraftInventory.java:197-203`, `:225-231`), and it provides the Forge item-handler capability per side (`:256-281`); the top's sided inventory allows insert and extract of slot 0 on every side (`common/tiles/crafting/TileThaumatoriumTop.java:204-214`) but exposes no item-handler capability, since it does not extend the inventory base (`:16`; the transport base is `common/tiles/TileThaumcraft.java:19`).
27. **A comparator reads the body's slot; the top has no comparator output.** Only the body half overrides the comparator hook, reporting the standard inventory-fullness value (`common/blocks/crafting/BlockThaumatorium.java:112-122`).
28. **The front face is the ejection direction and is never an Essentia input; there is no Essentia output at all.** The front is excluded from connectability, intake, and the pull probe (`common/tiles/crafting/TileThaumatorium.java:320-333`, `:236-259`), and both transport and container never emit Essentia (`:330-333`, `:360-363`).

### H. Lifecycle, break, and reload

29. **The machine's state survives reload in NBT: the slot, the stored aspects, the formula hashes, and the registering names.** The sync payload carries the stored amounts, the formula cap, and the hash array, and the world-save payload adds the registering names (`common/tiles/crafting/TileThaumatorium.java:86-127`, composed through the shared base `common/tiles/TileThaumcraft.java:42-56`; the inventory persistence is `common/tiles/TileThaumcraftInventory.java:170-187`). On read, the requirement copies are rebuilt from the catalog by hash and unresolved hashes are dropped (`common/tiles/crafting/TileThaumatorium.java:89-102`), while the client's copy of the names is blank (`:98`). Not persisted: the current pick, the heat state, the tick counters, and the top's link — the pick resets to none and is re-derived from the input catalyst by the run loop (`:65-79`, `:163-168`, `:175-184`), and the top re-links on its first ticks (`common/tiles/crafting/TileThaumatoriumTop.java:24-31`).
30. **Breaking either half converts the other to the alchemical construct block; the body drops its slot and destroys its stored Essentia silently.** Each half converts the other on break (`common/blocks/crafting/BlockThaumatorium.java:92-100`); the shared break path drops the tile inventory and, for Essentia transports that report a stored amount, pollutes the aura — but this machine reports zero stored amount and never spills (`common/blocks/BlockTCTile.java:54-65`; `common/tiles/crafting/TileThaumatorium.java:355-358`), so the stored Essentia is simply lost.
31. **The venting effect exists but nothing arms it.** Any client block event sets a seven-tick venting counter on the client (`common/tiles/crafting/TileThaumatorium.java:310-318`), and the client branch then emits vent particles around the front face (`:205-216`; the block-level forwarder is `common/blocks/BlockTCTile.java:67-71`) — yet no call site in the tree sends a block event to either half of the machine, so the effect is dormant as shipped.

## Rank-1 capture checklist

Reference setup for every step: the clean 1.12.2 profile whose only mods are the BETA26 jar and Baubles (`REF-0002` and the "Environment feasibility" section of [reference-catalog.md](reference-catalog.md)); record the profile, world seed, and game mode in a new `REF` entry before starting. The established session world is **creative**, which supplies the alchemical construct block (note that the separate Brass Block does not match the blueprint), the crucible, a heat source (lava, fire, Nitor, magma), jars, tubes, and a Mnemonic Matrix from the mod's creative tab without research; the `THAUMATORIUM` research itself and any formula research must be granted with the operator command between measurements, never during one. Carry a phial or jars holding the aspects a chosen formula needs.

- **T1 — Build and heat gate.** Stack alchemical construct blocks over a crucible and apply Salis Mundus without the research (no conversion), then with it: record the column converting to the machine and both halves facing the same way; right-click each half and confirm the same screen; then break the crucible beneath the body and record the body and top reverting to the construct block (items 3-4, 9).
- **T2 — No heat, then heat.** With the craft set up and no heat under the crucible, confirm nothing happens; add lava, then record the machine starting; repeat for fire, a Nitor, and magma; remove the heat and record the pause and the resume (items 14, 16).
- **T3 — Selection surface.** Insert a catalyst with several known matching formulas and record: the list appearing, the aspect requirement display and its fill bars as Essentia arrives, the registered/max counter with a Mnemonic Matrix attached (and the matrix popping off when detached), and both page arrows on a long list (items 7, 10-13).
- **T4 — One full craft, timed.** With one formula registered, a matching catalyst and a sufficient Essentia supply, record the entire run: the suction visible on tubes, the aspect drawn one unit at a time, the requirement bars filling, the craft completing with the output ejected through the front — into a chest placed in front, and as a dropped item with no chest — the catalyst consumed by exactly one, and the machine's store empty afterwards. Time it, and note whether any leftover Essentia (from a formula switch beforehand) disappears (items 18-23).
- **T5 — Pick behavior and formula switching.** Register two formulas sharing one catalyst and record which one runs; remove the running one through the GUI mid-craft and record whether the other takes over; register two formulas with different catalysts and bank Essentia for the idle one, then swap the input and record the leftover handling (items 17, 22).
- **T6 — Redstone and comparator.** Apply a signal at the body, at the crucible, and at the top in turn and record the pause; read the comparator output with an empty slot and a full stack (items 15, 27).
- **T7 — Reload and interruption.** Mid-craft, exit and re-enter the world: record the resumed machine (catalyst kept, full store kept, formula list kept, pick re-derived), and whether the client displays the active formula correctly; break the machine mid-craft and record that the broken half drops its own contents (the body's catalyst included), the stored Essentia is gone with no aura pollution, the other half converts to the alchemical construct block, and the crucible beneath stays a crucible (items 29-30).
- **T8 — The dormant effect.** If any interaction produces the front-facing vent particles, record it; otherwise record their absence (item 31).
