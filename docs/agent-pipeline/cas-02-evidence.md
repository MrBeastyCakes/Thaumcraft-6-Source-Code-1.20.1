## Reference behavior (source-derived)

### A. The invocation

1. **One caster item exists, and it is the Caster's Gauntlet.** The single registered caster is built from `ItemCaster` with area zero and named "Caster's Gauntlet" (`common/config/ConfigItems.java:275`; field `api/items/ItemsTC.java:138`; name `assets/thaumcraft/lang/en_us.lang:194`); the area only selects how wide an aura pool the item reads and drains from — the holder's own chunk, that chunk plus four neighbours, or a three-by-three chunk square (`common/items/casters/ItemCaster.java:106-131`, drain spread `:134-191`) — and no item uses the other two areas, so those branches are dormant in BETA26 (section F, item 37). The focus the caster casts from is carried as an item stack inside the caster's own tag (`common/items/casters/ItemCaster.java:202-231`).
2. **The cast pays first and casts second, server-side only.** The right-click handler refuses when no focus is inserted or the cooldown is active (`common/items/casters/ItemCaster.java:382-384`), books the activation delay before anything is paid (`:385`), steps aside for a sneaking pick when the graph contains a block-picking element (`:387-393`), returns success on the client without casting (`:394-396`), and on the server charges the focus's vis cost against the aura pool, runs the stored graph through the engine, and swings only when the cast goes through (`:397-402`).
3. **What is paid is the graph's committed complexity.** The vis cost is a fifth of the package complexity (`common/items/casters/ItemFocus.java:157-160`), scaled by the caster's consumption modifier — one minus the holder's vis discounts, floored at a tenth, and raised again by the vis-exhaustion potions (`common/items/casters/ItemCaster.java:194-200`; discount sources `common/items/casters/CasterManager.java:26-54`) — and drained from the aura around the holder (`common/items/casters/ItemCaster.java:134-191`). The activation time booked by the same click is the complexity over five times the complexity over four, floored at five ticks (`common/items/casters/ItemFocus.java:162-165`). The player-facing figure is the tooltip's vis-per-cast line (`common/items/casters/ItemCaster.java:243-248`; language `assets/thaumcraft/lang/en_us.lang:198`).
4. **Cooldowns are per-side maps keyed by entity id, and the delay is booked before the payment test.** `common/items/casters/CasterManager.java:350-355` and `:364-375`; because the booking happens at `common/items/casters/ItemCaster.java:385`, before the resource test at `:397`, a refused cast still costs its activation delay and a second click cannot re-enter inside the window (item 32).
5. **A caster-aware block, tile, or registered trigger absorbs the click before any cast.** `common/items/casters/ItemCaster.java:321-332`; and with a block-picking element in the graph, a sneaking right-click on a tile-less block stores a silk-touch snapshot on the caster item for the later effect to place (`:333-356`, store `:462-465`, read `:467-490`).
6. **The caster keeps its holder's aura readout current, because that readout is the pool casts are paid from.** Every ten ticks a held caster pushes its pool's aura chunk — vis, flux, base — to its holder's client (`common/items/casters/ItemCaster.java:260-269`, `:271-319`; payload `common/lib/network/misc/PacketAuraToClient.java:21`; client side `client/lib/events/HudHandler.java:47`).

### B. The engine walk

7. **Entry copies the graph, re-aims the root, mints a per-cast identity, and fires every effect's cast hook before the walk.** `api/casters/FocusEngine.java:57-71`: the stored package is copied per cast unless the caller owns a transient one (the pech's and the flux rift's casts pass the no-copy flag — `common/entities/monster/EntityPech.java:210-222`, `common/entities/EntityFluxRift.java:383-393`); the copy's root, when it has no supplies yet, is aimed from the caster's eyes along its look vector with the caster as the first target (`api/casters/FocusPackage.java:223-229`; `api/casters/FocusMediumRoot.java:54-57`); a fresh unique id is minted (`api/casters/FocusEngine.java:65`); every effect node in the graph, splits included (`api/casters/FocusPackage.java:107-127`), gets its cast hook (`api/casters/FocusEngine.java:66-68`; hook contract `api/casters/FocusEffect.java:34-36`); and the walk starts with no incoming supplies (`api/casters/FocusEngine.java:70`).
8. **The walk iterates the node list by index, and the index is the cursor.** Each step stamps the current index onto the package (`api/casters/FocusEngine.java:95`), repairs a missing parent link to the previous node (`:98-103`), binds the node to the package (`:105-107`), and multiplies the package's power by the node's own factor (`:109-111`). The walk is synchronized on the node list (`:87`) and the list itself is a synchronized list (`api/casters/FocusPackage.java:32`), because the same graph instance can be read off-thread while it runs.
9. **Dispatch is by element type, in a fixed order.** A nested package recurses and ends the outer walk (`api/casters/FocusEngine.java:113-116`); a medium executes once per incoming trajectory and, when it declares itself an intermediary, ends the walk (`:118-126`); a split modifier runs each of its packages against its own supplies and ends the walk (`:129-137`); any other modifier executes in place (`:138-140`); an effect executes once per incoming target (`:143-161`); and the default intermediary answer is negative unless a medium overrides it (`api/casters/FocusMedium.java:22-24`).
10. **Trajectories pair with targets by index when the counts allow, and every effect learns its target number.** `api/casters/FocusEngine.java:157-159`; the number is also what block-deferred effects stagger their work by (item 29).
11. **After a node runs, its supplies become the inputs of everything after it.** `api/casters/FocusEngine.java:164-167` — the medium's ray decides what the trailing effects can hit, and what a modifier's parents supply feeds the modifier's branches.
12. **The cursor is how an intermediary takes over the graph.** Everything after the medium is cut into a fresh package carrying the power accumulated so far and the same cast identity (`api/casters/FocusNode.java:61-73`, identity `:67`), which the projectile, cloud, mine, and spellbat re-run on their own trigger; a re-entry hands the triggering event's own trajectories and targets to the walk as its inputs, and the engine synthesizes a root for them when the trailing graph starts with anything else (`api/casters/FocusEngine.java:89-91`).
13. **A fresh id per cast keys a damage bookkeeping list so several hits from one cast all land.** For every entity target the engine records the target's id together with the cast id in a static list trimmed once it exceeds ten entries; the first hit registers, and any later hit from the same cast that arrives while the target still shows its invulnerability window zeroes that window so the damage applies (`api/casters/FocusEngine.java:147-155`, list `:174`; the id is minted at `:65` and travels into everything cut from the graph at `api/casters/FocusNode.java:67`). Two separate casts do not share a key; several effect nodes in one cast do (checklist T8).
14. **Without a medium in the trail, the caster is the target.** The root supplies the caster itself as its only target (`api/casters/FocusMediumRoot.java:44-57`), so an effect reached directly from the root resolves against the caster (checklist T1).

### C. The seven delivery mediums

15. **Touch is instantaneous, and its real work is the ray it supplies rather than its execute step.** Execute only broadcasts the beam effect (`common/items/casters/foci/FocusMediumTouch.java:96-107`); the trace happens when the engine pulls the node's supplies after the step — an entity ray with quarter-block padding first, then a block ray out to the reach distance, with the hit point, the entity, or the reach end becoming the replacement trajectory (`:47-94`; finder `common/lib/utils/EntityUtils.java:193`; touch uses the caster's own block reach and bolt a fixed sixteen — the reach choice `common/items/casters/foci/FocusMediumTouch.java:53`, `:80`; reach lookup `codechicken/lib/raytracer/RayTracer.java:185`). Effects then land on the traced target in the same walk.
16. **Bolt is Touch specialized into a sixteen-block zap.** It subclasses Touch, keeps its supply logic at the longer reach, and overrides execute with its own instant trace plus a zap packet whose colour is the average of the graph's effect colours and whose width is two-thirds of the cast power (`common/items/casters/foci/FocusMediumBolt.java:17`, `:40-71`).
17. **Projectile hands the rest of the graph to an entity.** Execute spawns `EntityFocusProjectile` with the trailing package, a launch factor of the speed setting over three, and the option mode, declaring itself an intermediary so the walk ends (`common/items/casters/foci/FocusMediumProjectile.java:46-60`); the entity is thrown from the caster's edge along the trajectory, ignoring the caster, with gravity of one-hundredth of a block per tick — half that while seeking (`common/entities/projectile/EntityFocusProjectile.java:53-70`); seeking options acquire a visible living target within sixteen blocks on a five-tick cadence (`:192-211`); on impact it queues the trailing graph on the server with the impact as the target and dies, or bounces off blocks first while the bouncy option is set — bouncy projectiles only fire on entity impacts — and it expires after twelve hundred ticks or when its thrower is gone (`:135-182`, `:186-190`). The entity carries the serialized graph to clients at spawn and through world saves (`:104-115`, `:117-133`).
18. **Cloud is a repeating area delivery with per-target limits.** Execute spawns `EntityFocusCloud` at the trajectory source with the radius and duration settings and declares an intermediary (`common/items/casters/foci/FocusMediumCloud.java:38-47`); every five server ticks the cloud gathers the living entities inside its radius plus a handful of random block hits, skips anything still inside a two-second per-target cooldown, re-arms that cooldown, and re-runs a copy of the trailing graph against that step's targets (`common/entities/projectile/EntityFocusCloud.java:155-211`; entity pass `:159-181`, block pass `:182-204`, run `:205-211`); entities and blocks share one static cooldown map keyed by entity id and block position, so overlapping clouds limit each other (`:172-175`, `:189-202`, `:217-220`); the cloud dies after its duration in seconds times twenty ticks or when its owner cannot be resolved (`:135-141`).
19. **Mine is a placed trap that arms itself and fires once.** Execute spawns `EntityFocusMine` at the trajectory source and declares an intermediary (`common/items/casters/foci/FocusMediumMine.java:38-47`); the entity arms on its first impact (`common/entities/projectile/EntityFocusMine.java:104-108`), waits out a forty-tick arming counter (`:120-124`), and then, every five ticks, finds the living entities within one block that match the friend-or-foe setting, runs the trailing graph once per found target, and dies (`:134-161`). Its armed state and its stored graph are part of its saved data, so a trap survives a reload armed (`:84-102`).
20. **Plan is an instant block work order with no entity at all.** The medium has no execute override — the base default does nothing (`api/casters/FocusMedium.java:26-28`) — and its value is the supply function: a sixteen-block block ray from the parent trajectory, then a walk from the hit over its own area — every non-air block in a cube around the hit for the full method, or the connected exposed run of the same block along the face for the surface method, sorted by distance from the hit — emitting one block target per block with the hit side (`common/items/casters/foci/FocusMediumPlan.java:62-89`, area walk `:164-185`, settings `:55-60`). The area size and axis come from the caster item's own area picks (`common/items/casters/CasterManager.java:223-348`); the medium is exclusive (`common/items/casters/foci/FocusMediumPlan.java:106-109`); and the trailing effects land on the block targets in the same walk, so for example a break focus harvests each planned block once.
21. **Spellbat spawns a companion that keeps the graph alive.** Execute places `EntitySpellBat` at the trajectory source with the trailing package and the friend setting, declaring an intermediary (`common/items/casters/foci/FocusMediumSpellBat.java:38-48`); the bat moves and fights for its chosen side (`common/entities/monster/EntitySpellBat.java:296-326`), and each bite — gated by a forty-tick attack pause and its short reach — runs the trailing graph against the bitten target on the server and costs the bat one health (`:275-287`); it dies after six hundred ticks or when its owner is gone (`:172-176`).
22. **Clients only ever render; the graph runs on the server.** The server sends touch's beam, bolt's zap, and each effect's impact burst to players within sixty-four blocks of the point (`common/items/casters/foci/FocusMediumTouch.java:104`, `common/items/casters/foci/FocusMediumBolt.java:69`, `common/items/casters/foci/FocusEffectFire.java:53`; payloads `common/lib/network/fx/PacketFXFocusEffect.java:29`, `common/lib/network/fx/PacketFXZap.java:23`, `common/lib/network/fx/PacketFXFocusPartImpact.java:27`; client-side rendering for example `common/lib/network/fx/PacketFXZap.java:49-51`), while the intermediary entities carry their serialized graph to tracking clients at spawn so their particle colours can come from it (`common/entities/projectile/EntityFocusProjectile.java:104-115`, `common/entities/projectile/EntityFocusCloud.java:143-154`).

### D. The modifiers, and the per-delivery arithmetic

23. **Split target and split trajectory cut the walk in half and scale everything beneath them to three quarters.** Reaching the split multiplies the containing package's power by three quarters (`api/casters/FocusEngine.java:109-111`; factor `api/casters/FocusModSplit.java:37-40`), then each split package runs with the split's own supplies as its inputs and the outer power multiplied in (`api/casters/FocusEngine.java:129-137`). The variants differ only in the supply they pass through — targets (`common/items/casters/foci/FocusModSplitTarget.java:34-37`) or trajectories (`common/items/casters/foci/FocusModSplitTrajectory.java:34-37`).
24. **Scatter forks each incoming trajectory and divides the power by half the fork count.** The supply function turns each parent trajectory into as many perturbed directions as the fork setting, spread by the cone setting (`common/items/casters/foci/FocusModScatter.java:45-64`), and the node's power factor is one over half the fork count (`:66-69`) — five forks means each fork carries two-fifths of the power. It is exclusive (`:76-79`).
25. **The power an effect finally receives is the product walked from the root.** The engine multiplies factors node by node in walk order (`api/casters/FocusEngine.java:110`) — cloud halves at its own node (`common/items/casters/foci/FocusMediumCloud.java:54-57`), spellbat takes a third (`common/items/casters/foci/FocusMediumSpellBat.java:50-53`), split takes three quarters, scatter takes the fork fraction — and the effect's execute receives that product as its final power (`api/casters/FocusEngine.java:158`), which a displaying effect converts into its damage figure (`api/casters/FocusEffect.java:28-30`, for example `common/items/casters/foci/FocusEffectFire.java:47-49`).
26. **Each delivery re-derives the arithmetic from the stored graph.** The package cut at the cursor carries the power accumulated up to the medium (`api/casters/FocusNode.java:61-73`), and each later trigger runs it afresh — a cloud pass copies it per pass (`common/entities/projectile/EntityFocusCloud.java:209`), a mine trigger per target (`common/entities/projectile/EntityFocusMine.java:155`), a bat bite per bite (`common/entities/monster/EntitySpellBat.java:282`), and the projectile runs its stored tail once at impact (`common/entities/projectile/EntityFocusProjectile.java:178`) — so a trailing modifier applies its factor once per delivery rather than accumulating across deliveries.

### E. Effect application

27. **An effect is called once per incoming target, and its return value is discarded.** `api/casters/FocusEngine.java:143-161`: for each target the engine passes the target, the paired trajectory, the final power, and the target number; the boolean an effect returns is never read, so an effect that refuses a target simply leaves it unchanged (`api/casters/FocusEffect.java:26` is the contract).
28. **Effects dispatch on target kind — entities take damage, states, or healing; blocks take direct edits or queued block work.** Fire damages and ignites, refusing fire-immune targets, and can light the block face when the burn setting is above zero (`common/items/casters/foci/FocusEffectFire.java:52-77`); air damages and knocks back along the trajectory when one is present (`common/items/casters/foci/FocusEffectAir.java:53-70`); frost damages and slows, and on block hits freezes water into temporary frosted ice around the impact (`common/items/casters/foci/FocusEffectFrost.java:64-89`); curse damages and applies a poison chain that weakens step by step (`common/items/casters/foci/FocusEffectCurse.java:59-101`); flux is magic damage only (`common/items/casters/foci/FocusEffectFlux.java:52-59`); heal heals the living for the power figure and damages the undead for half again as much (`common/items/casters/foci/FocusEffectHeal.java:53-64`); earth damages entities, and on blocks queues a harvest only when the block is soft enough for the power (`common/items/casters/foci/FocusEffectEarth.java:52-65`); break queues a harvest of the hit block with the silk and fortune settings and a delay that scales with the target number (`common/items/casters/foci/FocusEffectBreak.java:47-61`); exchange swaps the hit block for the block picked onto the caster, refusing without one (`common/items/casters/foci/FocusEffectExchange.java:46-66`); rift opens a temporary hole through the hit face, refusing the outer dimension with a failure sound (`common/items/casters/foci/FocusEffectRift.java:53-93`).
29. **Block work is deferred through server-side queues, which is also where the per-target staggering lives.** Break, earth, and exchange hand their block to the same event queues — a breaker entry carrying strength, silk, and fortune, and a swapper entry carrying the replacement block, with the delay wrapped on by the enqueue path rather than carried in the entry (`common/lib/events/ServerEvents.java:364`, `:375-397`; the break call `common/items/casters/foci/FocusEffectBreak.java:56`) — and those queues drain in the server tick, counting the delay down and running what is left (`common/lib/events/ServerEvents.java:105-152`).
30. **Impact feedback is per target; the cast sound is per cast.** Each effect sends its impact burst from the point of application (`common/items/casters/foci/FocusEffectFire.java:53`, the same pattern across the other effects), while the per-effect cast sound plays once for the whole graph through the cast hook, which runs before the walk (`api/casters/FocusEngine.java:66-68`, hook example `common/items/casters/foci/FocusEffectFire.java:100-102`).
31. **The repeated-hit rule is what lets several effect nodes in one cast all land on one target** — item 13: second and later hits from the same cast zero the target's invulnerability window, so a graph carrying two damage effects deals both hits where a single hit's timing would otherwise swallow the second (`api/casters/FocusEngine.java:147-155`).

### F. Failure, edges, and dormant paths

32. **The refusal paths and what each costs.** No focus, or an active cooldown: the click falls through to the item's default and nothing happens (`common/items/casters/ItemCaster.java:382-384`); insufficient aura vis: the server returns failure with no cast and no swing, but the activation delay was already booked on both sides (`:385`, `:397-402`); on the client every eligible click returns success before payment and the client never casts (`:394-396`).
33. **An empty trace is zero targets, not an error.** When touch or bolt finds neither entity nor block, its target supply is an empty array, the effect loop runs zero times, and only the medium's own feedback happens (`common/items/casters/foci/FocusMediumTouch.java:47-94`; bolt keeps Touch's supply logic — item 16 — and the engine's loop tolerates empty arrays because it tests the array, not its length — `api/casters/FocusEngine.java:145-161`). The plan's block ray behaves the same way (`common/items/casters/foci/FocusMediumPlan.java:79-88`). A medium-less graph never misses, because its only target is the caster (item 14).
34. **A failed entity spawn is silent.** The projectile, cloud, mine, and spellbat execute steps return the world's spawn result, and the engine ignores it (`common/items/casters/foci/FocusMediumProjectile.java:52`, `common/items/casters/foci/FocusMediumCloud.java:41`, `common/items/casters/foci/FocusMediumMine.java:41`, `common/items/casters/foci/FocusMediumSpellBat.java:42`; the medium branch reads no return value — `api/casters/FocusEngine.java:118-126`), so a delivery that cannot spawn is dropped without feedback.
35. **An intermediary with nothing behind it is an unguarded null path.** The projectile dereferences the package cut at the cursor without a null check (`common/items/casters/foci/FocusMediumProjectile.java:49-50`), and cloud, mine, and spellbat pass the same null-capable value straight into their entities (`common/items/casters/foci/FocusMediumCloud.java:40`, `common/items/casters/foci/FocusMediumMine.java:40`, `common/items/casters/foci/FocusMediumSpellBat.java:40`), which the cut function returns for an empty tail (`api/casters/FocusNode.java:72`). What protects the path in normal play is the editor's socket-completeness rule, which is client-side; the server's start gate checks node research, levels, and crystals but not socket completeness (`common/tiles/crafting/TileFocalManipulator.java:236-291`; sibling note [cas-01-evidence.md](cas-01-evidence.md), items 18-19).
36. **Lifetime and owner loss end active deliveries quietly.** The projectile dies after twelve hundred ticks or when its thrower is gone (`common/entities/projectile/EntityFocusProjectile.java:186-190`); the cloud after its duration in seconds times twenty ticks or when its owner cannot be resolved (`common/entities/projectile/EntityFocusCloud.java:135-141`); the mine after twelve hundred ticks or when its thrower is gone (`common/entities/projectile/EntityFocusMine.java:117-119`); the bat after six hundred ticks or when its owner is gone (`common/entities/monster/EntitySpellBat.java:172-176`).
37. **Dormant paths a port should not copy as live behavior.** The caster's area parameter only ever holds zero — there is a single registration (`common/config/ConfigItems.java:275`) — so the neighbour-chunk and three-by-three pool and drain branches are unreachable in BETA26 (`common/items/casters/ItemCaster.java:113-131`, `:149-188`); the item's private source-vector helper has no caller (`:360-377`); the projectile's no-touch flag is written twice and never read (`common/entities/projectile/EntityFocusProjectile.java:38`, `:46`, `:55`); and the inventory-wide vis drain helper has no callers in the tree (`common/items/casters/CasterManager.java:56-67`).
38. **Touch's supply logic assumes a player caster.** The reach line casts the caster to a player without a guard (`common/items/casters/foci/FocusMediumTouch.java:53`), and the target-supply entry checks the caster type before its own cast (`:76-80`); the entity casters that exist in the tree build projectile and cloud graphs only, never touch (`common/entities/monster/EntityPech.java:210-222`, `common/entities/EntityFluxRift.java:383-393`), so a port that lets non-player casters use touch graphs inherits a cast error path.

## Rank-1 capture checklist

Reference setup for every step: the clean 1.12.2 profile whose only mods are the BETA26 jar and Baubles (`REF-0002` and the "Environment feasibility" section of [reference-catalog.md](reference-catalog.md)); record the profile, world seed, and game mode in a new `REF` entry before starting. The session world is creative, which supplies the caster (the Caster's Gauntlet), the blank foci, and the aspect crystals from the mod's creative tab without research. Casting itself needs no research, but building the graphs does: grant the node keys with the operator command between measurements, never during one (`/thaumcraft research <player> <key>`, with its list, all, reset, and revoke forms — `common/lib/CommandThaumcraft.java:72-80`, `:89-105`).
