# Validation Matrix

Every change is validated at the lowest tier that can prove it, and promoted upward when it can affect saved state, the client, a server, or a release. The tiers are cumulative: a higher tier never replaces a lower one, and a parity claim is complete only when every applicable tier has passed with its result recorded.

Rules that apply to every tier:

- Record the outcome in the work item's handoff at `docs/agent-pipeline/handoffs/<ID>.md`, filling the `Automated evidence` and `Runtime evidence` fields.
- Keep human-readable scenario notes next to their work item as `docs/agent-pipeline/<work-item>-evidence.md`. JUnit tests belong under `src/test/java/thaumcraft/`, with small fixtures under `src/test/resources/thaumcraft/`, following the storage convention in `parity-evidence-index.md`. The current Forge run configurations load only `sourceSets.main`, so GameTests must remain in the loaded main mod source set until FND-01 explicitly wires and proves discovery from a dedicated GameTest source set. FND-01 must demonstrate that `runGameTestServer` discovers the selected convention before later work relies on it.
- Tiers above `Documentation-only` need Gradle or a game instance, so they resume only after the project owner lifts the budget hold; see `budget-hold.md`. While the hold is active, only the `Documentation-only` tier may be executed.
