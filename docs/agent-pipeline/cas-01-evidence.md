## Reference behavior (source-derived)

### A. The apparatus

1. **The machine is one block with one tile, registered as `wand_workbench` and named "Focal Manipulator".** The block constructor wires `TileFocalManipulator` and a stone sound (`common/blocks/crafting/BlockFocalManipulator.java:19-22`); the block declines the full-cube shape (`:24-34`); any activation opens GUI id 7 at the block position on both sides, with no research gate on opening (`:36-42`). It is registered at `common/config/ConfigBlocks.java:316` (field `api/blocks/BlocksTC.java:122`), the tile at `common/config/ConfigBlocks.java:378`, the name at `assets/thaumcraft/lang/en_us.lang:309`. It inherits the Thaumcraft creative tab (`common/blocks/BlockTC.java:20`, through `common/blocks/BlockTCDevice.java:16` and `common/blocks/BlockTCTile.java:17`), and the screen and container are mapped at `proxies/ProxyGUI.java:102` and `:171`.
2. **Its own recipe is an arcane workbench craft gated on stage 2 of `BASEAUROMANCY`, at a hundred vis and one earth plus one water crystal** (`common/config/ConfigRecipes.java:192`).
3. **The tile is a one-slot inventory whose real state is the map of nodes being edited, the focus name, and the pending vis charge.** Fields and constructor `common/tiles/crafting/TileFocalManipulator.java:32-55` (one slot, slot zero on the synced list); the sync payload carries the charge, the name, the crystal requirement copy, and the serialized node map (`:57-71`, `:73-85`); the base class funnels that same payload into the world-save form and the block-entity update packet (`common/tiles/TileThaumcraft.java:42-52`, `:64-74`), while the slot itself persists through the inventory base (`common/tiles/TileThaumcraftInventory.java:170-187`) and syncs through the synced-slot message (`:114-138`).
4. **The screen is a 231-square container screen: a node canvas in the middle, a parts palette on the left, a name strip on top, and cost readouts and the confirm button on the right** (`client/gui/GuiFocalManipulator.java:101-133`; the focus slot sits at the container's own coordinates `common/container/ContainerFocalManipulator.java:20-22`). In the world, a tile renderer draws the slot's focus item floating and spinning above the block and the required crystals orbiting it once a requirement exists (`client/renderers/tile/TileFocalManipulatorRenderer.java:35-48`, `:49-90`; registration `proxies/ProxyTESR.java:58`).
5. **Confirm rides the vanilla enchant-packet channel; a refusal plays the failure sound.** The button is enabled only while no charge is running and the client's validity check passes (`client/gui/GuiFocalManipulator.java:263`), clicking sends the enchant packet (`:155-158`), and the container forwards it to the tile's start path, playing the failure sound when the start returns false (`common/container/ContainerFocalManipulator.java:35-40`).

### B. The working graph model

6. **A node in the editor is a focus element plus its place in the tree.** `FocusElementNode` carries a canvas position, an id, a parent id, child ids, the two supply flags, a complexity multiplier, and the element instance (`common/tiles/crafting/FocusElementNode.java:10-29`); it serializes the geometry and flags, the element key, and every setting under `setting.<key>` (`:64-83`), and rebuilds by resolving the key in the engine registry and re-initializing the element's settings (`:43-62`).
7. **Elements are looked up by key in a registry that also backs the palette and the icons.** `api/casters/FocusEngine.java:13-31` (key-to-class, icon, and color maps; lookup instantiates a fresh element).
8. **Edits are made on the client and applied wholesale to the server tile.** The screen sends the entire node map and name as one message (`client/gui/GuiFocalManipulator.java:1098-1100`; wire form `common/lib/network/playerdata/PacketFocusNodesToServer.java:34-51`); the server handler clears the tile's map, adopts the message's map and name, and marks the tile dirty (`:53-72`) — the only later re-derivations from that map are the craft-start gates (item 18). The name field rides its own packet on every keystroke (`client/gui/GuiFocalManipulator.java:167-175`; `common/lib/network/playerdata/PacketFocusNameToServer.java:36-49`).
9. **The tree is anchored by a blank root, and removing or swapping the focus in the slot clears it.** A reset empties the map and re-adds a `FocusMediumRoot` at id zero, selecting its first child socket (`client/gui/GuiFocalManipulator.java:852-859`); the screen resets on an empty slot or after the tile's reset flag is raised (`:318-332`), and the tile raises that flag and clears its own state whenever the slot contents change on either side (`common/tiles/crafting/TileFocalManipulator.java:92-108`).
10. **Adding a node replaces the selected one, culls its descendants, and re-opens the child sockets.** A palette click adds at the selected socket (`client/gui/GuiFocalManipulator.java:561-573`); right-clicking a placed node re-adds its parent's class as a sibling (`:547-555`); the add routine removes the replaced subtree, keeps the old canvas position, mints the id and the parent link, and creates child sockets — one for a normal node, two for a split (`:701-786`, descendant culling `:692-699`, id minting `:685-690`). Child sockets exist only while the node itself supplies something (`:746-776`).
11. **Each socket records what its parent supplies, and empty sockets are drawn with badges.** A new node's target and trajectory flags come from the element's own supply profile (`:738-739`), and the canvas draws the available-supply badges beside an empty socket's connector (`:407-453`). A layout pass keeps the tree readable, centering split branches and aligning splits under non-split parents (`:788-850`).

### C. The editing surface

12. **The palette is the element registry filtered by three rules: strict research, exclusivity, and supply matching.** Every registered element must pass the strict knowledge test (`client/gui/GuiFocalManipulator.java:910-914`); the root is excluded in practice because it declares no required supply (`:925-927`), while the explicit key test beside it compares against a `thaumcraft.ROOT` key that no element carries and is inert (`:915-917`); the keys of an exclusive element already placed are excluded, and no further medium is offered once an exclusive medium is placed (`:895-906`, `:922-924`, `:936-939`); the element must accept one of the supplies the selected socket's parent provides (`:925-949`); and the survivors are listed mediums first, then effects, then modifiers, each alphabetically by key (`:952-957`); the strict test itself is `api/capabilities/ThaumcraftCapabilities.java:70-88`.
13. **The selected node's settings are edited with spinner pairs, and every change syncs the whole graph.** One spinner is built per setting of the selected node, skipped while that setting's research is unknown (`client/gui/GuiFocalManipulator.java:969-986`; the on-canvas setting labels `:471-486`); the spinner decrements at its left arrow and increments at its right (`client/gui/plugins/GuiFocusSettingSpinnerButton.java:41-53`) and renders the setting's current value text (`:35-36`); the click path re-sends the node map (`client/gui/GuiFocalManipulator.java:155-165`).
14. **Hover tooltips explain a node before it is used.** The palette and canvas tooltips list the element's name and description, its complexity — colored when the duplicate multiplier applies — the accumulated power multiplier when it is not one, and an effect's damage or healing figure at the placed power (`:272-306`).
15. **The name strip defaults to the focus's current display name and edits sync immediately.** The screen initializes the field from the tile's name, falling back to the slot's stack display name (`:135-143`, `:1091-1097`), and typing updates the tile's name and sends it (`:167-175`).

### D. Complexity, costs, and gates

16. **Complexity sums node by node, and each repeated pattern costs half again as much as the previous occurrence.** While the tree is walked, each node's multiplier is half of one more than the occurrence number of its element key — the first occurrence pays the node's own complexity in full, the second pays half again (multiplier one and a half), the third pays double (multiplier two) (`common/tiles/crafting/TileFocalManipulator.java:173-184`; the screen computes the same for its readout `client/gui/GuiFocalManipulator.java:1004-1013`); a node's own complexity is derived from its settings (section F); the total is the sum of complexity times multiplier (`common/tiles/crafting/TileFocalManipulator.java:182`). The player-facing statement of the surcharge is in the language file (`assets/thaumcraft/lang/en_us.lang:1558`).
17. **The imprint price is ten vis per complexity point plus a fifth of the focus's cap, an experience figure from the square root of the complexity, and one crystal per aspect-carrying node.** `common/tiles/crafting/TileFocalManipulator.java:264-265`; the crystal list is built by walking the nodes and adding one unit for each node that carries an aspect (`:241-263`). Worked example for the smallest base focus (root, touch, fire at defaults): touch and fire are complexity 2 each, both at the first-occurrence multiplier, so the total is 4; on a lesser blank focus that prices at 43 vis (4×10, plus 15/5), two experience levels (one or the rounded square root of the complexity, whichever is larger — item 20), and two crystals — one aversion and one fire. The player-level version of the price (crystals, vis, experience, with complexity driving cast cost and cooldown) is in the language file (`assets/thaumcraft/lang/en_us.lang:1558`).
18. **The start gates are ordered, and experience is spent before the crystals are checked.** Every node must exist and its research must be strictly known (`common/tiles/crafting/TileFocalManipulator.java:244-250`); an insufficient level refuses before anything is spent (`:266-269`); the level cost is deducted next, but the crystal-carrying test comes after it (`:270-286`), so a player who lacks a crystal loses the experience with nothing else happening; the carried crystals are then consumed, the requirement copy kept for display, and the start sound plays (`:287-295`). Two guards behind that path are effectively unreachable from the editor: the no-aspect refusal (`:296-298`) and the always-true array-length check above it (`:280`) — every medium and every effect carries an aspect, and a complete editor tree always ends in one or more effects, because effects are the only elements that supply nothing and therefore have no required child sockets (section F, item 10).
19. **The screen recomputes and shows all of that itself, and gates the confirm button on its version of it.** Cast cost as complexity over five, the vis figure as above, an experience figure, the crystal requirement as hoverable icons (`client/gui/GuiFocalManipulator.java:1024-1056`), and validity as: within the focus's cap, no blank socket, crystals carried, and the tile's own experience figure within the player's level (`:1064`).
20. **Two client-side wrinkles sit in that readout.** The displayed experience figure is one or the rounded square root of the complexity, whichever is smaller (`:1026`), while the server charges one or that same rounded root, whichever is larger (`common/tiles/crafting/TileFocalManipulator.java:265`) — above trivial complexity the displayed figure is always the smaller. And the validity test reads the tile's own experience figure (`client/gui/GuiFocalManipulator.java:1064`), which is neither in the sync payload nor in the save payload (`common/tiles/crafting/TileFocalManipulator.java:57-85`) and is written only by the server-side start path (`:265`), so a client copy keeps its constructor value of zero (`:50`) and the client-side level gate never refuses. Both are source observations; both need a session to judge (see the unverified list).
21. **The charge is a once-per-second step that drains the aura.** While a charge is pending, the tile wakes every twenty ticks, drains up to twenty vis, sends the client spark effect, re-syncs, and completes when the charge reaches zero, calling the commit (`common/tiles/crafting/TileFocalManipulator.java:137-165`; the spark branch `:306-317`); the drain targets the block's own aura position, or nine positions one chunk apart when the vis charger sits above the manipulator (`:110-129`). The charger accepts the manipulator as a base exactly like the arcane workbench (`common/blocks/crafting/BlockArcaneWorkbenchCharger.java:40`, `:59`, `:72`; registration `common/config/ConfigBlocks.java:297`; the nine-fold description `assets/thaumcraft/lang/en_us.lang:1642`). Removing the focus mid-charge aborts: the charge resets and the failure sound plays (`common/tiles/crafting/TileFocalManipulator.java:138-142`).
22. **The cap on complexity is the item's own maximum.** `common/items/casters/ItemFocus.java:31-36` (constructor argument stored as the maximum; single-item stacking) and `:167-169`; the three blank foci carry 15, 25, and 50 (`common/config/ConfigItems.java:276-278`; names `assets/thaumcraft/lang/en_us.lang:195-197`), and an item that is not a focus cannot occupy the slot at all (`common/container/slot/SlotFocus.java:23-25`; the tile repeats the test `common/tiles/crafting/TileFocalManipulator.java:301-304`).

### E. The commit, and the item it writes

23. **Completion rebuilds the graph from the editor map and writes it into the focus item.** The commit rebuilds the complexity multipliers the same way the start did, walks from the node with id zero, and turns each split's children into sub-packages (`common/tiles/crafting/TileFocalManipulator.java:168-213`); it then clears the item's cached color tag, sets the item's display name from the name field, writes the package through `ItemFocus.setPackage`, replaces the slot contents, and clears the editor state (`:215-234`, completion sound `:220`).
24. **The stored payload is a small tree: identity fields, power and complexity, and the node list.** `api/casters/FocusPackage.java:171-207` (uid, execution index, dimension, caster uuid, power, complexity; per node its type, key, every `setting.<key>`, and for splits the nested packages) and its reader `:129-169`; nodes are re-instantiated through the registry, and an unknown key is silently dropped (`:150-151`). Settings are stored as their effective values, not list positions, and are re-derived on read by walking the value space upward from its bottom until the stored value matches (`api/casters/NodeSetting.java:26-37`, `:51-59`; the two setting flavors `:79-107`, `:109-136`) — so a stored value outside the declared list or range lands on the top of that list or range.
25. **What the item adds on top: a vis cost and an activation time derived from complexity, plus two display caches.** Cost is complexity over five (`common/items/casters/ItemFocus.java:157-160`) and the activation time multiplies the complexity divided by five by the complexity divided by four, with a five-tick floor (`:162-165`); how the caster spends those belongs to `CAS-02` and `CAS-03` (`common/items/casters/ItemCaster.java:382-397`, `common/items/casters/CasterManager.java:351-373`, boundary citations only). The caches: a color averaged from the effect elements, written lazily and cleared at every commit (`common/items/casters/ItemFocus.java:38-70`; `common/tiles/crafting/TileFocalManipulator.java:222-224`), and a sorting hash stored under `srt` (`common/items/casters/ItemFocus.java:72-82`) that the commit does not clear — it is reused when foci are ordered for caster sharing (`common/items/casters/CasterManager.java:85-110`, boundary citation).
26. **Persistence, precisely: the item payload travels with the stack; the editor tree belongs to the block and is never rebuilt from the item.** The package tag written at commit is read back only by the tooltip and the caster paths (`common/items/casters/ItemFocus.java:84-100`; callers `common/items/casters/CasterManager.java:229` and six sites in `common/items/casters/ItemCaster.java:335`, `:386`, `:417`, `:433`, `:449`, `:475`); no call to that reader exists anywhere in the block, tile, container, or screen — the screen's only use of the item is its maximum complexity (`client/gui/GuiFocalManipulator.java:997-998`) — so placing an already-configured focus and committing again replaces the whole payload rather than editing what is stored, and the editor starts from a blank root instead (item 9). On the block side, the node map, the name, the charge state, and the requirement copy are part of the tile's saved payload and are restored on load (`common/tiles/crafting/TileFocalManipulator.java:57-85` through `common/tiles/TileThaumcraft.java:42-52`), and the same payload is what the update packet hands to the client (`common/tiles/TileThaumcraft.java:64-74`). What does not survive: any edit sequence once the slot contents change — the same listener that clears the server's charge and requirement raises the client's reset flag (`common/tiles/crafting/TileFocalManipulator.java:92-108`).
