## Reference behavior (source-derived)

### A. The Golem Press and the golem's parts

1. **The reference calls it the Golem Press, and it is built as a dust-triggered multiblock.** Five ordinary blocks form it: a cauldron, an anvil, an upward-facing piston, and a stone table in a two-by-two ground plan, with a block of iron bars floating directly above the piston's cell — the blueprint's four horizontal rotations are tried so any facing of that layout fits (`common/config/ConfigRecipes.java:117-124`; the fit search `common/lib/crafting/DustTriggerMultiblock.java:61-101`). Right-clicking the arrangement with Salis Mundus runs the trigger: while the player still lacks the `MINDCLOCKWORK` research the search refuses silently (`common/lib/crafting/DustTriggerMultiblock.java:42-59`; the research key's entry `assets/thaumcraft/research/golemancy.json:71`), otherwise the source blocks are swapped for their targets on a delayed server pass — piston to the press block, the other four to invisible placeholder blocks that drop the original items when broken (`common/lib/crafting/DustTriggerMultiblock.java:124-181`; targets `common/config/ConfigRecipes.java:117-121`; drops `common/blocks/misc/BlockPlaceholder.java:64-84`, `common/blocks/crafting/BlockGolemBuilder.java:52-54`). The dust item drives the click: sneaking passes it through, the dust is consumed unless the player is in creative, the click's effects run on both sides while the swap body itself is server-guarded and the sparkle burst is client-only (`common/items/resources/ItemMagicDust.java:34-57`; the guard `common/lib/crafting/DustTriggerMultiblock.java:126`). All five blocks present as "Golem Press" in the language file (`assets/thaumcraft/lang/en_us.lang:423`, `:434-437`); the press block itself renders nothing and is not on any creative tab (`common/blocks/crafting/BlockGolemBuilder.java:25-33`, `:40-50`), and a client renderer attached to the press tile draws the press model in its place (`proxies/ProxyTESR.java:73`). Opening it is a right-click on the press block or on any placeholder within one block of it (`common/blocks/crafting/BlockGolemBuilder.java:99-105`; `common/blocks/misc/BlockPlaceholder.java:91-109`; the screen id's two resolutions `proxies/ProxyGUI.java:104-105`, `:173-174`). Breaking any part restores real blocks — the placeholder teardown and the press block's own removal (`common/blocks/crafting/BlockGolemBuilder.java:61-97`).

2. **A craft starts from the screen and is paid in items plus Machina essentia.** The screen's craft action packs the chosen parts into one long, sends it to the tile, and locks the screen (`client/gui/GuiGolemBuilder.java:410-416`); the server validates the output slot (empty or a matching placer), checks the merged component list against adjacent storage and the player's inventory, consumes it, and sets a cost meter (`common/tiles/crafting/TileGolemBuilder.java:192-222`). The cost is twice the golem's trait count plus one per component item (`:212-215`); the tile then pulls Machina one unit per five ticks — suction of 128 while a craft is owed, connectable on the four horizontal faces and the bottom, and pushable from a neighbouring transport (`:127-147`, `:229-243`, `:245-253`, `:294-301`) — the aspect's key is `machina` (`api/aspects/Aspect.java:198`) — until the meter empties and the finished golem placer appears in the output slot carrying its props tag (`common/tiles/crafting/TileGolemBuilder.java:133-146`; output slot accepts only placers `:224-227`). The screen can also ask the tile to check component availability without crafting (`:54-70`, `:180-190`).

3. **The press survives a reload mid-craft.** The tile's craft state — chosen golem long, current cost, maximum cost — is written through the sync-NBT hooks, which the tile base also uses for save data, and the output slot rides the base inventory's NBT (`common/tiles/crafting/TileGolemBuilder.java:88-114`; `common/tiles/TileThaumcraft.java:42-56`; `common/tiles/TileThaumcraftInventory.java:170-187`), so an unloaded press resumes drawing essentia when it ticks again. Client visibility has three surfaces: the container's window properties carry the cost readouts while a screen is open (`common/container/ContainerGolemBuilder.java:53-85`); the tile's sync payload — the golem long and the cost figures — rides its sync-NBT hooks to tracking clients at craft start and completion (`common/tiles/crafting/TileGolemBuilder.java:88-106`, `:175`, `:219` through `common/tiles/TileThaumcraft.java:58-74`), and the client branch of the tile's own update animates the press from those fields (`common/tiles/crafting/TileGolemBuilder.java:149-170`); and the sole message the tile sends is a targeted answer to the requesting player's component check (`:65`).

4. **The builder screen gates parts by strict research and previews the derived numbers.** Each of the five categories is a filtered list of the registered parts whose research array the player knows strictly (`client/gui/GuiGolemBuilder.java:94-142`), each dial is a pair of scrolling arrows around a hover button (`:181-245`), and the middle shows the trait icons, hearts, armour and damage of the current combination (`:246-263`) beside the component list, the Machina aspect icon, and the running cost (`:266-311`); the craft button only enables when every component is present (`:300-311`). The container is a plain one-slot-plus-inventory window whose cost readouts travel as window properties (`common/container/ContainerGolemBuilder.java:23-34`, `:53-85`), and it refuses a tile the viewer has walked away from (`:83-85`; the distance rule `common/tiles/TileThaumcraftInventory.java:193-195`). A creative player can bypass the press: the placer item's creative entries include prepared presets — a blank skeleton plus a smart-headed variant, an iron smart golem with claw arms, and a thaumium smart golem with breaker arms (`common/golems/ItemGolemPlacer.java:39-63`).

5. **The upgrade surface is the parts catalogue: six materials, five heads, five arms, four legs, and four addons, registered in a fixed order.** Materials, with their health modifier, armour, damage, and traits (`common/golems/GolemProperties.java:200-205`): Greatwood 6/2/1 and Light; Iron 20/8/3 with Heavy, Fireproof, Blastproof; Clay 10/4/2 with Fireproof; Brass 16/6/3 and Light; Thaumium 24/10/4 with Heavy, Fireproof, Blastproof; Void Metal 20/6/4 with the self-repair trait. Heads: clockwork (no traits), smart (Smart, Fragile — the learning head), armoured smart (Smart), perceptive (Scout, Fragile), biothaumic (Scout, Smart, Fragile) (`:206-210`). Arms: basic, fine (Deft, Fragile), claws (Fighter, Clumsy, Brutal), breakers (Breaker, Clumsy, Brutal), darts (Fighter, Clumsy, Ranged, Fragile, with a dart-launching function that fires magically created darts) (`:211-215`, the launching function `common/golems/parts/GolemArmDart.java:21-36`). Legs: walker, roller (Wheeled), climber (Climber), flyer (Flyer, Fragile) (`common/golems/GolemProperties.java:216-219`). Addons: none, armour plating (Armored, Heavy), aggression module (Fighter), carry frame (Hauler) (`:220-223`). Traits resolve with oppositions — a later contribution removes its opposite from the assembled set, so Armored cancels Fragile, Deft cancels Clumsy, and Heavy cancels Light — and the cancelling contribution is itself dropped, so a smart golem with armour plating ends with neither Fragile nor Armored (`common/golems/GolemProperties.java:43-73`; the trait list and the three opposing pairs `api/golems/EnumGolemTrait.java:6-36`). Each part also carries its component list, and the data expands it into the craft's item cost — two bases, one mechanism, then the parts' own entries with base and mechanism placeholders resolved through the material (`common/golems/GolemProperties.java:157-197`). Player-facing names and descriptions for every part and trait are in the language file (`assets/thaumcraft/lang/en_us.lang:606-696`), and the design flow — press, five components, listed components in inventory, the trait/heart/armour/damage readout, Machina supply, placement, colour by dye — is stated in the `MINDCLOCKWORK` research page (`:1699`).

### B. The golem entity: spawn, storage, and reload survival

6. **One spawn path, and it stamps ownership at placement.** Right-clicking a solid block face with the placer item spawns the golem at the adjacent position and stamps it owned, valid-spawn, and owner-UUID, applies the item's `props` long and an optional banked `xp` value, runs initial spawn (home is the placement spot), and consumes the item unless the player is in creative (`common/golems/ItemGolemPlacer.java:87-118`). A whole-tree search finds no other construction of the entity. The placer's tooltip shows the material name and trait list, and for smart heads a rank line with progress (`:65-85`).

7. **Ownership and spawn validity live in the construct base.** Two data parameters carry an owned bit and an optional owner UUID (`common/entities/construct/EntityOwnedConstruct.java:29-42`, `:44-64`), the construct never despawns (`:90-92`), and an entity whose valid-spawn flag was never set removes itself on its first server tick, and the placement path sets the flag immediately after spawning (`:94-106`). Non-owners who right-click get the not-owned message and nothing else (`:189-201`; the string `assets/thaumcraft/lang/en_us.lang:1091`). The construct takes the owner's team and never targets its members (`common/entities/construct/EntityOwnedConstruct.java:155-176`; the clear-on-same-team in its own update `:94-98`), cannot drown, and plays mechanical sounds (`:66-88`).

8. **What the entity writes to disk — and what it never writes.** The golem's own NBT covers five keys: the props long (parts plus rank), the home position, the flags byte, the rank experience, and the colour, with the read path re-applying the derived attributes (`common/golems/EntityThaumcraftGolem.java:385-404`); the base adds the valid-spawn flag and the owner UUID string, with the legacy owner-name conversion (`common/entities/construct/EntityOwnedConstruct.java:108-139`). Never written: the current task and its id (transient fields, `common/golems/EntityThaumcraftGolem.java:84-85`), the task map itself (server-only and rebuilt empty — the seal-side derivation of task ephemerality is [aut-01-evidence.md](aut-01-evidence.md) item 29), and the carried stack, which lives in the entity's hand slots (finding 18) and so depends on the base game's save chain — this is the note's most load-bearing open question (T5). Home and follow state do survive: on the first tick after a load, a golem away from its recorded home is sent back to it — the first-run home call that resolves as a teleport to the home column's first free cell, not a walk (`common/golems/EntityThaumcraftGolem.java:259-271`; the resolution `:350-383`).

9. **Synced entity data: what every client knows.** Four data-manager entries exist: the props long split across two ints, one int packing the colour byte and the flags byte, and a climbing byte (`common/golems/EntityThaumcraftGolem.java:108-115`, `:134-155`, `:773-778`); the construct base adds two more of its own — the owned bit and the optional owner UUID (`common/entities/construct/EntityOwnedConstruct.java:29-42`). Clients therefore hold the full part layout and rank (inside the props bits), the colour, the follow/stay and in-combat flags, the climbing state, and the owner identity. Rank experience is a plain field, not one of those entries (`common/golems/EntityThaumcraftGolem.java:77`), and the task, home, and carry contents never leave the server through the mod's channels (finding 24). Emotes ride entity status bytes instead (`common/golems/EntityThaumcraftGolem.java:308-330`).

10. **Derived attributes are a function of parts and rank — with one tree-text caution.** The derived set (`common/golems/EntityThaumcraftGolem.java:170-196`): maximum health is 10 plus the material's health modifier, reduced to three-quarters when fragile, plus one per rank; home radius is 32, or 48 with the scout head; follow range 40, or 56; step height 0.6, or 0.5 when wheeled; a flight move helper for flyer legs; attack damage is zero unless the golem is a fighter, then the material's damage, raised to one-and-a-half times for brutal (or plus one when that is larger), plus a quarter per rank; armour from the material, one-and-a-half (or plus one) when armoured, three-quarters when fragile (`:243-252`); movement speed is 1 plus 2.5 percent per rank, plus 20 percent light, minus 17.5 percent heavy, minus 33 percent flyer, plus 25 percent wheeled (`:332-334`). Caution for a port reading the tree: the fragile factors are rendered in the tree text as a cast of the fraction itself — which would zero the value — but the shipped jar's compiled methods multiply the value by three-quarters (bytecode read with javap against the `REF-0002` jar — `REF-0006` in [reference-catalog.md](reference-catalog.md) — to settle it), so those two tree sites (`:172-174`, `:248-250`) and their copy in the builder preview (`client/gui/GuiGolemBuilder.java:246-257`) are a decompiler artifact, not reference behavior.

### C. The task pipeline on the entity side

11. **The entity carries two claim goals, a home goal, and, in follow mode, a follow goal.** The default list runs the entity-claim goal, the block-claim goal, the home goal, plus watch and idle looks (`common/golems/EntityThaumcraftGolem.java:99-106`); a rebuild pass clears and re-adds them: follow mode replaces both claim goals with the follow goal, and fighters add swimming (ground navigators only), the arm's ranged attack task when the arms declare one, a melee task, owner-hurt targets while following, and a hurt-by target (`:198-231`). The follow goal chases the owner from beyond ten blocks, stops within two, and teleports the golem when the path fails and the owner is at least twelve blocks away (`common/golems/ai/AIFollowOwner.java:42-56`, `:76-97`). The home goal idles, then walks the golem home whenever it has no task and is more than a couple of blocks away, stepping randomly toward home when it is very far (`common/golems/ai/AIGotoHome.java:23-47`, `:49-60`).

12. **Claiming is a sorted scan with a chain of gates.** A claim attempt is cooldown-gated, is suppressed while a live task is held, and on success notifies the owning seal through its task-started hook (`common/golems/ai/AIGoto.java:43-61`). The candidate lists come from the per-dimension task map, filtered by type, skipping reserved tickets, insertion-sorted by squared distance minus 256 per priority point — the entity list also suspends tickets whose entity has died (`common/golems/tasks/TaskHandler.java:49-80`, `:82-116`; the per-golem binding gate in both sorters tests a field no producer ever sets, finding 26). Each candidate then passes a chain: the trait gate — a locked seal only accepts its owner's golems, required and forbidden tags are enforced (`common/golems/ai/AIGoto.java:131-150`); the task's own eligibility test, which rejects a colour mismatch between golem and seal when both carry colours and then defers to the seal's own check (`api/golems/tasks/Task.java:140-148`; the seal-side derivation of lock and colour is [aut-01-evidence.md](aut-01-evidence.md) items 23 and 25); the golem's home-distance test; a destination-validity hook; and a reachability probe. On success the ticket is reserved and an accept emote is set (`common/golems/ai/AIGotoBlock.java:42-57`, `common/golems/ai/AIGotoEntity.java:36-51`).

13. **Navigation and approach are per-target-kind.** The block goal moves to the chosen neighbouring cell, or to the task position itself, at the golem's trait-adjusted speed (`common/golems/ai/AIGotoBlock.java:32-40`), choosing as its approach cell the closest horizontal neighbour that does not block movement (`:59-73`) and probing reachability against the path's final point (`:75-94`); the entity goal chases the target entity, with a stop range of three and a half blocks plus the square of half the target's width (`common/golems/ai/AIGotoEntity.java:29-34`, `:53-68`). The shared update loop measures distance each attempt; while out of range it re-issues movement every fifth update and, if the golem has not moved since the previous check, requests a random step toward the target; a claim is abandoned after a thousand updates without completion (`common/golems/ai/AIGoto.java:74-111`, `:70-72`). Navigation is trait-chosen: ground golems use a golem node processor with door entry and cauldron step-up handling (`common/golems/ai/PathNavigateGolemGround.java:27-30`, `:82-96`; choice at `common/golems/EntityThaumcraftGolem.java:336-338`), climbers use the climbing navigator, and flyers use an air navigator with its own direct-line test and a flying move control (`common/golems/ai/PathNavigateGolemAir.java:18-24`, `:30-54`; `common/golems/EntityThaumcraftGolem.java:780-822`).

14. **Completion is the seal's answer, attempted on a ten-tick cadence.** In range, the golem asks the handler to complete the ticket; the handler defers to the owning seal's completion hook and marks it complete when no seal exists or the seal says yes (`common/golems/tasks/TaskHandler.java:118-129`; the attempt loop with its pause `common/golems/ai/AIGoto.java:96-109`). When the goal ends, a completed ticket is suspended and the reservation released, with an abort emote for an uncompleted reserved ticket (`:113-123`). Completion and reservation both extend the ticket's lifespan, and every call of the reservation setter adds two minutes in either direction (`api/golems/tasks/Task.java:64-71`, `:97-104`).

15. **Lifespans are counted in seconds and swept once per second.** Tickets default to five minutes (`api/golems/tasks/Task.java:34-54`); the sweeper keeps unsuspended unexpired tickets — decrementing each by one — and drops the rest, notifying each dropped ticket's seal through its suspension hook (`common/golems/tasks/TaskHandler.java:131-148`). The sweep runs from the server world tick once per second, inside the same pass that flushes the aura chunk-dirty list (`common/lib/events/ServerEvents.java:171`).

16. **Working a target is a fake player, and the arm swing is broadcast.** The interaction helper spawns a synthetic player at the golem's position with the golem's held stack and clicks or right-clicks the block face — when a placement would collide it first nudges the golem one block along the face — then awards one rank experience and swings the golem's arm; whatever the synthetic player could not hold is dropped at the golem (`common/golems/GolemInteractionHelper.java:29-57`, `:65-88`). The swing is sent to watchers as an animation packet (`common/golems/EntityThaumcraftGolem.java:753-762`). The two seals that click blocks drive this helper (`common/golems/seals/SealUse.java:88-90`, `common/golems/seals/SealHarvest.java:130`).

### D. Ranks and earned experience

17. **Rank is earned only by smart golems, from completed work, and it is banked with the golem when it is retrieved.** Experience enters the golem's rank field only when it carries the smart trait and only on the server (`common/golems/EntityThaumcraftGolem.java:617-620`); the advance threshold from a rank is the next rank number squared times one thousand — one thousand for the first rank — and on advance the threshold is subtracted, the rank is rewritten into the props data, and a level-up sound plays under an emote, while a golem at rank ten earns nothing further (`:621-635`). Experience arrives one point per finished task across the production seals (`common/golems/seals/SealFill.java:102`, `common/golems/seals/SealGuard.java:91`, `common/golems/seals/SealProvide.java:129`, `common/golems/seals/SealHarvest.java:126`), one point per synthetic click (`common/golems/GolemInteractionHelper.java:51`), and eight points for a kill (`common/golems/EntityThaumcraftGolem.java:597-599`); the banked figure travels in the placer item and is restored on re-placement (finding 6), while the rank itself lives in the props bits and is what the tooltip's rank line displays (`common/golems/ItemGolemPlacer.java:69-77`).

### E. The golem's carry slots

18. **The carry slots are the entity's hand slots, one or two of them.** The golem stores carried stacks in the first two equipment-slot values — main hand, plus off hand only when the carry-frame addon is present (`common/golems/EntityThaumcraftGolem.java:638-658` for the hold path: an empty slot takes the stack, a matching stack is merged up to its limit, the leftover is returned; the same shape for retrieval `:660-689`, where an emptied main hand is refilled from the off hand, for capacity `:691-703`, and for the queries `:705-741`). An empty slot counts as a full stack's headroom; the capacity is reported in items of the queried kind, and the API contract says the hold call returns whatever the golem could not take (`api/golems/IGolemAPI.java:26-54`). The held stack is drawn in the golem's hand and shifts the arms into a carrying posture on clients that have it (`common/golems/client/RenderThaumcraftGolem.java:102`, `:250-263`).

19. **Pickup, death, and delivery dispositions.** The owner's sneak-right-click releases the reservation, drops the carried stacks, mints a placer item with the props long and the banked rank experience, and removes the entity (`common/golems/EntityThaumcraftGolem.java:430-442`; the drop loop `:502-508`). Death releases the reservation, drops the carried stacks server-side, and rolls the golem's component list into loot at thirty percent plus fifteen per looting level with randomly reduced counts (`:491-500`, `:510-521`). Because the placer carries only props and experience, a retrieved golem loses its colour — the research page says so in player terms (`assets/thaumcraft/lang/en_us.lang:1699`). The seal-side transfers that load and empty these slots are [aut-01-evidence.md](aut-01-evidence.md) items 27 and 30; the entity-side primitives they call are the hold/retrieve pair above — the empty seal loads the hand from the attached container (`common/golems/seals/SealEmpty.java:80`), the store seal inserts what is held and tops the hand back up (`common/golems/seals/SealFill.java:87-99`), the pickup seal stores a collected drop (`common/golems/seals/SealPickup.java:97`), the provide seal loads a request's item, hands leftovers back, and retrieves for delivery (`common/golems/seals/SealProvide.java:124`, `:154`, `:171`), the use seal clicks with the held stack (`common/golems/seals/SealUse.java:80-90`), and the harvest seal replants from the hand (`common/golems/seals/SealHarvest.java:170`).

### F. Ownership and control

20. **Commanding a golem is owner-only.** The bell toggles follow/stay only for the owner who knows the `GOLEMDIRECT` research (`common/golems/EntityThaumcraftGolem.java:444-465`; the two messages `assets/thaumcraft/lang/en_us.lang:697-698`; the research entry `assets/thaumcraft/research/golemancy.json:106-115`) — following clears the home anchor, staying re-anchors home at the golem's position with the scout-adjusted radius (`common/golems/EntityThaumcraftGolem.java:450-463`). Dye recolours for the owner, mapping the dye's registry order to the colour value as sixteen minus the index (`:467-485`; the dye table `common/config/ConfigAspects.java:610`; the client tint `common/golems/client/RenderThaumcraftGolem.java:162-163`). A name tag passes the interaction through to whoever holds it (`common/golems/EntityThaumcraftGolem.java:427-429`), and an owner's right-click with any other item is swallowed silently (`:467-488`).

21. **Where ownership bites for automation: the seal lock, tested from the golem side.** A locked seal only accepts tasks from a golem whose owner id equals the seal's owner string, and the same gate enforces required and forbidden traits (`common/golems/ai/AIGoto.java:131-150`, the lock test `:136`; the seal-side derivation of the lock and of the colour rule is [aut-01-evidence.md](aut-01-evidence.md) items 23 and 25). The seal configuration screens and retrieval are not owner-gated — the port must not infer a symmetric rule (cross-referenced, [aut-01-evidence.md](aut-01-evidence.md) item 24).

22. **Home is the leash of drawn work.** The home radius gates which tasks a golem will accept (finding 12) and drives the return-home goal; a golem hurt by world geometry or the world floor teleports to its home anchor (`common/golems/EntityThaumcraftGolem.java:406-418`), and the teleport resolves to the home column's first free cell above the anchor, reverting if the destination is not clear (`:350-383`).

### G. Multiplayer

23. **Tracking and rendering registration.** The entity registers with sixty-four block tracking, three-tick updates, and the velocity flag (`common/config/ConfigEntities.java:101`); the client binds its renderer by class (`proxies/ProxyEntities.java:137`), which caches part models per entity and redraws them when the entity's client flag says to (`common/golems/client/RenderThaumcraftGolem.java:96-110`). The visual layer is `CLI-02`'s.

24. **What crosses the wire — and what never does.** Synced: the part layout, rank, colour, follow/stay and in-combat flags, and climbing (finding 9). Broadcast on events: the emote status bytes, drawn as particle bursts client-side (`common/golems/EntityThaumcraftGolem.java:308-330`; senders `:453`, `:460`, `:631`, `common/golems/ai/AIGotoBlock.java:51`, `common/golems/ai/AIGotoEntity.java:45`, `common/golems/ai/AIGoto.java:116`, `common/golems/seals/SealPickup.java:116`; one handled status code is never sent by any golem path); arm swings to watchers (`common/golems/EntityThaumcraftGolem.java:753-762`); and the press tile's craft state through its sync payload at craft start and completion plus the container's window properties while a screen is open (finding 3). Never sent by the mod: rank experience, the current task and the task map, the home anchor, and the carried stacks — the last depends on the base game's equipment channel (unverified list; T7).

25. **Divergence classes to hunt at rank one.** (a) Rank progress is invisible to every client while the golem is placed — only a pickup materializes it in the placer's tooltip, so two clients must be compared at that moment. (b) Carried-item visibility for a second client. (c) Task state is wholly invisible — a watching client sees work but nothing that names the task or its seal (the owner identity does ride the base class's synced parameters — finding 9). (d) A second player's interaction surface on someone else's golem is one status message, and the golem does not pause. (e) Follow/stay crosses as the synced flags (finding 9): clients see the mode flip alongside the emote and the resulting motion; the command itself is server-applied. (f) Seal-side edits are per-player ([aut-01-evidence.md](aut-01-evidence.md) items 19 and 24); the visible coupling is which golem starts working.

### H. Dormant and edge paths

26. **Dead or unwired plumbing a port must not copy as live behavior.** The task-id lookup branch on the golem can never run — its id field is initialized to a sentinel and no producer assigns a real ticket id, so `getTask` always answers from the direct reference (`common/golems/EntityThaumcraftGolem.java:85`, `:604-610`); a static experience-per-rank constant is declared and never read (`:86`); the sorters' per-golem binding gate tests a task field that no production site ever sets (`api/golems/tasks/Task.java:73-79`; gates `common/golems/tasks/TaskHandler.java:58`, `:91`); the golem package's targeting AI class and its interface are referenced only by each other, while the turrets use their own inner classes (`common/golems/ai/AINearestValidTarget.java:21-25`, `common/golems/ai/ITargets.java:4-8`, `common/entities/construct/EntityTurretCrossbow.java:401-419`); and the task class's own save/load methods are commented out in the tree (the seal-side derivation of deliberate task ephemerality is [aut-01-evidence.md](aut-01-evidence.md) item 29; the commented block `api/golems/tasks/Task.java:169-223`).

27. **Edge behaviors worth a capture.** Damage rules: cactus immunity outright, fire immunity with the fireproof trait, explosions capped with blastproof, and the home teleport for wall or floor damage (`common/golems/EntityThaumcraftGolem.java:406-420`); the spawn path does not test the destination cell for clearance (`common/golems/ItemGolemPlacer.java:95-105`), so a golem can appear overlapping a block and is then rescued by its own recovery logic (finding 22); self-repair heals one point every forty ticks with the repair trait against every hundred without (`common/golems/EntityThaumcraftGolem.java:284-286`); a combat golem drops its target when the target dies, when a ranged golem's target exceeds a squared distance of one thousand twenty-four (about thirty-two blocks), or when the target is a player and the server has PVP off (`:275-283`); and the smart-head rank line only appears on placers whose props carry the smart trait (`common/golems/ItemGolemPlacer.java:69-77`).

## Rank-1 capture checklist

Reference setup for every step: the clean 1.12.2 profile whose only mods are the BETA26 jar and Baubles (`REF-0002` and the "Environment feasibility" section of [reference-catalog.md](reference-catalog.md)); a fresh creative world with its seed recorded in a new `REF` entry before the session. The creative session supplies the surfaces: the press's five constituent blocks are vanilla blocks, and the mod's creative tab carries Salis Mundus and every golem placer preset (items on the mod tab `common/items/ItemTCBase.java:17-23`, `:44-54`; press parts `common/config/ConfigRecipes.java:117-121`; placer presets `common/golems/ItemGolemPlacer.java:39-63`). The operator command surface `/thaumcraft research <player> <list|all|reset|<key>>` and `/thaumcraft reload` are the setup levers between measurements and must not be used during one (`common/lib/CommandThaumcraft.java:50-51`, `:58-112`; the reload form `:64-70`). Machina essentia for the press comes from a smelter-and-tube line charged with a Machina-bearing item — for example an iron door carries Machina five (`common/config/ConfigAspects.java:382`). Placement of the press and every structure starts with a recorded position and screenshot so the reload steps can compare exact cells.

- **T1 — The press, assembled and opened.** Build the five-block press (cauldron, anvil, upward piston, stone table; iron bars above the piston's cell) in a fresh cleared area. Right-click the piston with Salis Mundus while knowing nothing and record that nothing happens; grant `MINDCLOCKWORK` between measurements and repeat — record the swap in place (the piston position now opens the press), the press model, the "Golem Press" name on the blocks, and the screen opening from the press block and from each surrounding block; then break one placeholder and record the original block returning to the player. Also record that sneaking with the dust does nothing to the structure (items 1-2; bounded to one press).
- **T2 — The screen, the parts catalogue, and the research gate.** Open the press and cycle every dial; record the five categories, the trait icons, hearts/armour/damage changing with each part, the component list, the Machina icon, and the cost figure. Record one part that its research has not exposed as absent (breaker arms without `GOLEMBREAKER`), then grant that research between measurements, reopen, and record it present; repeat the observation for one material (`MATSTUDVOID`) and one leg (`GOLEMFLYER`) — bounded to three grant pairs (items 4-5).
- **T3 — A craft end-to-end, and the press across a reload.** Pick a basic configuration, stock its listed components, and feed Machina to a side or the bottom of the press. Record: the cost reading against the predicted figure (twice the trait count plus one per component item — count the displayed list), the cost falling by one about every five ticks, the press animation, the placer appearing in the output slot, and its tooltip; then start a second craft, save and reload the world at mid-cost, and record the press continuing from its stored cost (items 2-3; bounded to two crafts).
- **T4 — Placement, identity, and control.** Place a golem on a side face; record the spawn cell, the consumption of the placer (not in creative), no-despawn while the player is away, right-click with an empty hand (nothing and no other use fired), dye recolouring with the tint visible, name tag naming, sneak-pickup returning a placer whose tooltip matches the configuration, and re-placement showing the colour cleared. Then walk around a large obstacle and record the golem's return toward its placement spot (items 6-7, 19-20, 22; bounded to one golem).
- **T5 — Reload survival (the acceptance slice).** With the T6 collect seal briefly in place, let a golem load a stack into its hand. Record the golem's parts, colour, and flags; save and reload; then record each of the following against the pre-reload state: parts and colour present, home behaviour unchanged, rank progress as shown by a pickup tooltip, whether the carried stack is still in its hand (the open question — itself a finding either way), and that no task survives (seals re-mint only). Re-place the retrieved golem and record the fresh-identity behaviors of findings 6 and 19 (items 8-9, 17-19; bounded to two reloads).
- **T6 — The task loop end-to-end (the core acceptance).** Place a collect seal over a chest with a matching item and a store seal on the chest itself, then drop ten matching items nearby. Record: the accept emote, the golem walking to each drop and loading it into its hand — the collect seal alone only fills the hand, never depositing — and then the same golem taking the store seal's task and inserting the held stack into the chest — the store task grants one rank experience and the collect task none, and rank accrues only on a smart-headed golem (read the figure by picking the golem up once and inspecting the tooltip; items 17, 18-19). Then place a second seal and a second golem and record which golem claims which ticket; remove one seal at mid-task and record the golem abandoning (ticket suspension) and returning home; record whether the delivered amounts match the dropped amounts exactly (items 11-16, 18-19; bounded to two golems, two seals, ten items).
- **T7 — Ownership and multiplayer.** If a second client is available (otherwise record the step as not-run — the same gap as `FND-01`'s dedicated-server procedure): have the second player right-click the first player's golem and record the not-owned message with the golem continuing; attempt the bell's follow toggle on it and record nothing changing; record what the second client sees of the golem — parts, colour, swing, emotes — and whether the carried item is visible; at a pickup, record both clients' reading of the placer tooltip's rank line. Then repeat the same interactions as the owner and record the contrasts (items 17, 20-21, 24-25; bounded to one golem).
- **T8 — Ranks and the upgrade effects.** Give a golem a smart head and grant `GOLEMDIRECT` if needed for control. Run T6's loop (or kill mobs with a fighter golem) until the first rank-up; record the emote and the level-up sound, and the tooltip's rank and progress before and after (first rank at one thousand experience — the threshold is the next rank squared times one thousand, `common/golems/EntityThaumcraftGolem.java:617-636`); note that a non-smart golem never accrues (same citation). Then one golem per effect, one observation each: wheeled (faster, no jumping), flyer (flight, slower), climber (vertical), hauler (two carried stacks), breaker arms (block breaking), dart arms (ranged attacks), armour plating (armour line), and a guarded task with the aggression module — recording the derived-stat change shown on placement for each (items 5, 10, 17; bounded to the first rank and one observation per effect).
